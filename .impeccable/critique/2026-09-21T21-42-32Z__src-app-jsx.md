## Design Specificity Verdict

**Split verdict, and this is the core answer to "por que parece IA": the content is bespoke, the chrome is template-grade.**

**LLM assessment:** The domain logic is real, specific, unforgeable work — BRAND_GROUPS conglomerate ownership, the HEV-vs-mild-hybrid inclusion rule, PCD/ICMS price banding, the two-path (own-a-car vs. don't) savings calculator normalized per 10.000km. None of that drops into a generic template. What sits on top of it is the part that reads as AI-generated: all four modals (Tutorial, MyCarForm, Compare, and mostly Insurance) copy the identical "mobile bottom-sheet" recipe — position:fixed, inset:0, width:100% — stretched unmodified across every viewport including desktop (confirmed live: the mobility form's paragraph spans ~1686px on a 1745px window). Car photography is unnormalized (editorial BMW shots next to flat BYD product cutouts), which in dark mode produces glaring floating white rectangles — the fastest "nobody art-directed this" tell in the app. Persona icons are stock Lucide defaults shared by every SaaS dashboard template, despite automotive-specific icons already sitting unused in the same icon import. The base shape — pill filter row, badge-soup card grid, expandable detail with radar chart — is the generic "AI sleek dashboard" skeleton with car data poured into it.

**Deterministic scan:** The static CLI detector (markup/CSS regex rules) returned zero findings — clean by that measure. But the **live rendered-DOM overlay found 489 anti-pattern instances**: ~300 undersized-UI-text (functional labels at 9.5-10px, e.g. "Potência", "Vão livre", "PHEV", "HÍBRIDO"), ~116 low-contrast pairs, and ~80 tiny-text instances. Only ~2 color pairs and ~5 label strings account for nearly everything — meaning it's not scattered noise, it's the *same repeated card-grid component* applied identically across ~100 rendered cards, which is itself evidence of the cookie-cutter-grid tell. Most notable: **the brand gold #C89B3C fails WCAG AA as text** — 2.3:1 on cream, 2.6:1 on white, against a 4.5:1 requirement. This is a static-scan blind spot (it only exists at runtime with real computed styles) that the live overlay caught and the design review's own gut read of "the palette is used with intention" needs one caveat added to: the *choice* of navy/gold is correct and intentional, but the *specific shade of gold used for small text* is a genuine accessibility bug, not a brand problem — the app's own dark-theme code already keeps a lighter accentSoft (#E4C377) for exactly this reason in one place; it just isn't used everywhere gold text appears.

**Visual overlays:** Live overlay ran via an injected script in a fresh tab; 489 findings printed to console, summarized above. No gradients, glassmorphism, glow blobs, or decorative clip-paths were observed in either theme — the surface treatment itself is restrained, not a typical "AI slop" gradient-and-glow surface. The tell here is structural (unmodified stock patterns, unnormalized imagery) and technical (text size/contrast), not decorative excess.

## Overall Impression

This is a well-researched, financially-honest Brazilian EV comparison tool wearing a correct brand palette on top of a generic dashboard skeleton, with real accessibility bugs baked into the small print. The "cara de IA" feeling is real and has three concrete sources: (1) one bottom-sheet modal recipe copy-pasted across four different modals and every viewport, (2) unnormalized manufacturer photography creating visual noise, and (3) ~500 live-rendered instances of text too small or too low-contrast to read comfortably — mostly one repeated card component multiplied by ~100 cards. None of this requires touching the D&B palette or type system, which are both already correctly applied — it requires giving the chrome the same care the domain logic already got.

## What's Working

1. **The mobility/savings calculator's domain modeling** — two distinct paths (own a car / don't), maintenance normalized per 10.000km with a methodology tooltip, auto-fill from a curated Brazilian best-seller list. Real product thinking, not generic form-building.
2. **The spotlight tutorial** — highlights actual live DOM elements via getBoundingClientRect/scrollIntoView tied to real refs, so it teaches the actual screen rather than a canned onboarding-library carousel.
3. **Theme-aware accent logic** — accent2 deliberately flips (gold-on-navy in dark, navy-on-cream in light) with code comments explaining why, so primary actions keep correct contrast and brand hierarchy in both themes.

## Priority Issues

**[P0] Brand gold text fails WCAG contrast at scale (~116 live instances)**
Why it matters: #C89B3C at 2.3-2.6:1 against cream/white is unreadable for a meaningful share of visitors, and it's the brand's own signature color failing on the brand's own surfaces — the opposite of "respecting the identity manual."
Fix: swap gold-on-light text uses to the already-defined accentSoft/a darkened variant that clears 4.5:1, reserving raw #C89B3C for large text, icons, and fills where contrast rules don't apply.
Suggested command: /impeccable harden

**[P0] Modal system is one unmodified mobile pattern stretched across every viewport**
Why it matters: confirmed live that the mobility form's title/paragraph spans ~1686px on a 1745px window — this is the single biggest "assembled, not designed" tell, and it actively hurts readability at desktop width. InsuranceModal alone caps at 640px, an unexplained inconsistency with the other three.
Fix: give every modal a shared maxWidth (~560-640px) centered on desktop as a real dialog; reserve edge-to-edge bottom-sheet for an actual mobile breakpoint.
Suggested command: /impeccable layout

**[P1] ~380 instances of undersized/tiny UI text (9.5-11px functional labels)**
Why it matters: concentrated in the repeated card-grid component (spec labels, badges) — multiplied by ~100 rendered cards, this is the single largest mechanical finding and directly hurts legibility for every visitor on every card.
Fix: raise the card's functional-text floor to 11-12px minimum; audit the one shared component rather than hunting per-card.
Suggested command: /impeccable typeset

**[P1] Inconsistent photography treatment breaks visual unity, especially in dark mode**
Why it matters: raw manufacturer photos (editorial vs. white-cutout) at a fixed contain-frame produce glaring floating white rectangles in dark mode next to full-bleed lifestyle shots — nothing unifies the photographic language.
Fix: apply a consistent frame treatment (subtle scrim, unified canvas color, or letterboxing) so every card reads as one photographic system regardless of source image.
Suggested command: /impeccable polish

**[P1] Badge/pill overload flattens card hierarchy**
Why it matters: up to 4 same-weight badges per card (fuel type, wallbox, "melhor para", PCD hint, HEV disclaimer) give no signal about which matters most; every card looks equally busy.
Fix: establish a priority order — one primary badge visible, the rest behind "+2 more" or moved into the detail panel.
Suggested command: /impeccable distill

**[P2] Spec grid wraps into jumbled label/value collisions on long values**
Why it matters: long values (e.g. "PHEV combinado (motor a combustão + elétrico)") wrap directly against the label with no separation, producing cramped, hard-to-parse text — the one place the otherwise-crisp comparison UI visibly breaks.
Fix: stack label-above-value for long-value rows instead of forcing single-line space-between.
Suggested command: /impeccable harden

**[P3] No keyboard escape hatch; unlabeled modal close button; generic persona iconography**
Why it matters: Escape doesn't close any modal (confirmed live); the mobility modal's close icon has no aria-label (empty accessible name); persona icons are stock Lucide defaults shared by unrelated dashboard templates despite automotive-specific icons already unused in the same import.
Fix: bind Escape to close the top-most modal, add aria-labels to icon-only controls, swap 2-3 persona icons for more distinctive/automotive-coded marks.
Suggested command: /impeccable polish

## Persona Red Flags

No filter by range/battery, no shareable comparison URL, and compareIds isn't persisted — a power user narrowing finalists across sessions loses selection state on refresh.
